# Журнал изменений

## P1 — Drom manual, фотографии и vision

- APIpoint переведен на официальный единый POST `/api/call`, Bearer token и nested paths.
- Добавлены offers, confidence, стоимость запроса и последовательный Carprices fallback.
- Добавлены manual Drom URL validation без сетевых запросов и структурированная FSM-анкета.
- Добавлены Telegram photo/document/media-group metadata, дедупликация, порядок и лимиты.
- Добавлены Qwen vision client, строгая ConditionAssessment validation и один JSON repair.
- Добавлены deterministic blocking risk, параллельная orchestration и частичные статусы.
- Добавлены P1 SQLite migration, уникальная idempotency key и защита повторных платных вызовов.
- Добавлен пересчет сохраненного анализа с новой ценой без APIpoint и vision.
- Обновлен подробный отчет рынка, фотографий, вложений и экономики.

## P0 — достоверная экономика

- Добавлены строгие Pydantic-модели автомобиля, рынка, фотографий, видимых дефектов,
  состояния, ремонта и результата сделки.
- Добавлен APIpoint client на `httpx.AsyncClient`: конфигурируемые adapters, приоритет
  Avgcarprice → Carprices, один retry, валидация цены, fallback и TTL-кэш.
- Реальный контракт APIpoint не выдуман: без URL, parameter map и price path клиент возвращает
  `NotConfiguredError`, а анализ — `NO_RESULT`.
- Добавлен версионируемый локальный справочник ремонта с региональными коэффициентами,
  раздельным учетом CONFIRMED/POSSIBLE и предупреждением для неизвестных кодов.
- Добавлен `DealEngine` с формулами на `Decimal`, fixed expenses, risk reserve, отрицательным
  ROI и детерминированными verdict BUY/WATCH/PASS/NO_RESULT.
- Удален LLM из определения рынка, стоимости ремонта, финансовых показателей и verdict.
- Добавлен обязательный owner allowlist, выполняемый middleware до обработчиков и платных API.
- Добавлены mock/unit-тесты доменных схем, APIpoint, каталога, формул, verdict и безопасности.
- Устаревшие LLM-коммерческий промпт, fallback-рынок и неиспользуемые расчетные функции удалены.

Остальные записи ниже описывают предыдущие итерации и сохранены для истории.

## Текущая поставка

Каждый пункт ниже относится к текущей версии проекта, а не к ранее опубликованному варианту.

- **Добавлено сейчас:** локальное хранилище SQLite через `aiosqlite` и асинхронный
  SQLAlchemy 2.0 вместо PostgreSQL.
- **Добавлено сейчас:** автоматическое создание `bot_database.db` при первом запуске.
- **Добавлено сейчас:** хранение JSON-полей расчетов в колонках `TEXT` с явными
  `json.dumps()` и `json.loads()`.
- **Добавлено сейчас:** автоматическое удаление старых расчетов — у каждого пользователя
  остаются только пять последних записей.
- **Добавлено сейчас:** команда `/history`, показывающая до пяти последних расчетов
  текущего Telegram-пользователя.
- **Добавлено сейчас:** команда `/history <ID>` для просмотра сохраненного подробного отчета.
- **Добавлено сейчас:** обязательная проверка `telegram_id` при открытии отчета, исключающая
  просмотр расчетов другого пользователя.
- **Добавлено сейчас:** регистрация history-роутера в общем aiogram-диспетчере.
- **Добавлено сейчас:** автоматическая инициализация и корректное асинхронное закрытие
  SQLite engine в жизненном цикле приложения.
- **Добавлено сейчас:** зависимости `aiosqlite` и SQLAlchemy 2.0; зависимости PostgreSQL
  исключены.
- **Добавлено сейчас:** Windows PowerShell-инструкция по установке, запуску, получению
  токенов, резервному копированию SQLite и устранению неполадок.
- **Добавлено сейчас:** тесты ограничения истории пятью записями, JSON round-trip,
  разделения пользовательских историй и защиты от просмотра чужого расчета.
- **Добавлено сейчас:** INFO-запись об успешном запуске после проверки Telegram API через
  `getMe`; токены при этом в журнал не выводятся.
- **Добавлено сейчас:** корректный обмен Yandex OAuth-токена на IAM-токен перед обращением
  к Foundation Models вместо неподдерживаемой передачи OAuth-токена напрямую.
- **Добавлено сейчас:** диагностические записи о трех неудачных попытках YandexGPT и явное
  сообщение пользователю вместо сохранения фиктивного нулевого отчета.
- **Добавлено сейчас:** получение сырых рыночных цен через YandexGPT, когда официальный API
  и локальный fallback не дали данных; вся агрегация цен выполняется только в Python.
- **Добавлено сейчас:** fallback-цены для «Лада 2114 Самара» 2011 года и тест, не допускающий
  повторного появления нулевого рынка для этого сценария.
- **Добавлено сейчас:** явная переменная `YANDEXGPT_ENDPOINT` со значением OpenAI-совместимого
  Chat Completions API Yandex Cloud и возможностью переопределения через `.env`.
- **Добавлено сейчас:** поддержка `YANDEX_CLOUD_API_KEY` с заголовком `Api-Key`; OAuth → IAM
  сохранен как альтернативный способ авторизации.
- **Добавлено сейчас:** запрос YandexGPT переведен на формат `model/messages/max_tokens`
  и разбор `choices[0].message.content` без подключения запрещенной библиотеки `openai`.
- **Добавлено сейчас:** два отдельных шага FSM — вставка описания объявления и ручное
  перечисление повреждений, замеченных пользователем на фотографиях.
- **Добавлено сейчас:** описание объявления и видимые повреждения передаются во все
  релевантные промпты рынка, типичных проблем, ремонта и риска.
- **Добавлено сейчас:** переменная `YANDEXGPT_MODEL_URI` в `.env`; endpoint и модель
  выводятся при успешном старте бота.
- **Добавлено сейчас:** безопасный аудит каждого обращения к ИИ — ID, попытка, endpoint,
  модель, HTTP-статус и usage без промптов, пользовательского текста и секретов.
- **Добавлено сейчас:** единый профессиональный промпт перекупщика `full_analysis.txt` вместо
  разрозненных запросов рынка, ремонта и риска.
- **Добавлено сейчас:** новая структура результата — рынок региона/РФ, четыре группы ремонта,
  два бюджета подготовки, риск, ликвидность, осмотр, торг и коммерческий вердикт.
- **Добавлено сейчас:** недоверенная арифметика ответа модели полностью пересчитывается в
  Python, включая отрицательный ROI и исключение potential-ремонтов из бюджета.
- **Добавлено сейчас:** новый подробный HTML-отчет и безопасная отправка длинного отчета
  несколькими Telegram-сообщениями без превышения лимита 4096 символов.
